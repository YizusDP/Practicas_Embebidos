GPIO a fondo

¿Qué es, exactamente, un pin GPIO?

GPIO (General Purpose Input/Output) es un pin cuyo comportamiento NO está fijo de fábrica — el software decide, en tiempo de ejecución, si es entrada o salida, y qué valor tiene.

Como salida

El pin fuerza un voltaje (0V o 3.3V) que otro circuito puede leer — así encendemos un LED.

Como entrada

El pin mide el voltaje que otro circuito le está aplicando — así leemos un botón.

GPIO a fondo

Numeración: BCM vs física — la confusión más común

El mismo pin tiene dos números distintos según cómo lo nombres — y mezclarlos es la causa #1 de "por qué no enciende el LED si sí lo conecté".

Nuestra tabla de conexión (sección 5 del documento) usa BCM — es lo que libgpiod espera. Si consultan un diagrama en internet que use numeración física, van a conectar el pin equivocado.

GPIO a fondo

Niveles eléctricos: la regla de oro

GPIO es 3.3V — nunca 5V.

A diferencia de un Arduino clásico (5V), los pines de la Raspberry Pi NO son tolerantes a 5V. Conectar una señal de 5V a un pin GPIO puede dañar permanentemente el chip.

0V = nivel lógico 0. ~3.3V = nivel lógico 1. Si en el futuro conectan un sensor de 5V, necesitarán un divisor de voltaje o un level shifter — nunca la señal directa.

Corriente máxima — por qué la resistencia es obligatoria

Por pin

16 mA máx.

Límite absoluto de un solo pin.

Total combinado

~50 mA máx.

Sumando todos los pines GPIO activos a la vez.

Un LED sin resistencia puede pedir 20-30 mA — por encima del límite seguro. La resistencia de 220Ω que pusieron en el circuito no es "buena práctica opcional", es lo que evita dañar el pin.

GPIO a fondo

Resistencias pull-up / pull-down

Un pin de entrada sin conexión definida "flota" — puede leer 0 o 1 al azar por ruido eléctrico. La resistencia pull fuerza un valor por defecto.

Pull-down (lo que usamos hoy)

Resistencia a GND — el pin lee 0 en reposo, y 1 solo cuando el botón conecta a 3.3V.

Pull-up (alternativa)

Resistencia a 3.3V — el pin lee 1 en reposo, y 0 cuando el botón conecta a GND.

La Raspberry Pi también tiene resistencias pull internas, activables por software (sin componente físico) — hoy las armamos externas y visibles a propósito, para que el circuito completo quede claro.

GPIO a fondo

Funciones alternas — el mismo pin, distintos trabajos

Cada pin puede configurarse en uno de varios modos (ALT0 a ALT5) además de GPIO genérico — el mismo pin físico puede hablar I2C, SPI o UART según cómo se configure.

Esto es exactamente lo que usaremos en la Práctica 3: los mismos pines de hoy, reconfigurados por software para hablar el protocolo I2C o SPI en vez de encender/apagar directo.

Evolución del hardware

¿El GPIO es igual en toda Raspberry Pi?

En el laboratorio todos trabajan con RPi3 o RPi4 — pero vale la pena saber que la arquitectura del GPIO cambió en la RPi5, por si algún día usan una o encuentran código/tutoriales que ya no aplican igual.

RPi3 y RPi4

GPIO integrado directo en el SoC

En toda Raspberry Pi antes de la 5, el GPIO conecta directo al procesador principal — es un periférico memory-mapped más, dentro del mismo chip que la CPU. Exactamente el mecanismo de memory-mapped I/O que ya vimos en la clase de mapa de memoria.

RPi5

GPIO se muda a un chip aparte: RP1

La RPi5 introduce RP1, un chip de E/S separado, diseñado por la propia Raspberry Pi, conectado al BCM2712 por un enlace PCIe de 16 Gb/s. GPIO, USB, Ethernet y cámara/pantalla ya no viven en el procesador principal — viven en RP1.

Por qué esto nos importa hoy

Por eso usamos libgpiod desde el día 1

Librerías viejas como RPi.GPIO o pigpio acceden directo a los registros del SoC por memoria — funcionan en RPi3/4, pero se rompen en RPi5, porque ahí el GPIO ya no está en el SoC.

libgpiod habla con el kernel a través del dispositivo /dev/gpiochipN — el kernel es quien sabe si debe ir al SoC o a RP1. El mismo código en C que escribimos hoy funciona igual en una RPi4 o en una RPi5, sin cambiar una línea.

Parte C · LEDs desde C 1/2

leds.c

nano leds.c
#include <gpiod.h> #include <stdio.h> #include <unistd.h> #define CHIP "gpiochip0" #define N_LEDS 4 int main(void) { int pines[N_LEDS] = {17, 27, 22, 23}; struct gpiod_chip *chip = gpiod_chip_open_by_name(CHIP); struct gpiod_line *lineas[N_LEDS]; for (int i = 0; i < N_LEDS; i++) { lineas[i] = gpiod_chip_get_line(chip, pines[i]); gpiod_line_request_output(lineas[i], "leds", 0); }
Parte C · LEDs desde C 2/2

leds.c — patrón y compilación

for (int ronda = 0; ronda < 5; ronda++) { for (int i = 0; i < N_LEDS; i++) { gpiod_line_set_value(lineas[i], 1); usleep(150000); gpiod_line_set_value(lineas[i], 0); } } for (int i = 0; i < N_LEDS; i++) gpiod_line_release(lineas[i]); gpiod_chip_close(chip); return 0; }

Parte D · Botón por polling

boton_polling.c

#include <gpiod.h> #include <stdio.h> int main(void) { struct gpiod_chip *chip = gpiod_chip_open_by_name("gpiochip0"); struct gpiod_line *boton = gpiod_chip_get_line(chip, 5); struct gpiod_line *led = gpiod_chip_get_line(chip, 17); gpiod_line_request_input(boton, "boton_polling"); gpiod_line_request_output(led, "boton_polling", 0); while (1) { int estado = gpiod_line_get_value(boton); gpiod_line_set_value(led, estado); } }

Parte F · Reto final — sin código de partida

Semáforo peatonal

Aquí no hay código para copiar — solo reglas. Diseñen e implementen semaforo.c desde cero con lo que ya saben.

  • 3 LEDs simulan un semáforo vehicular (rojo=17, amarillo=27, verde=22) con ciclo automático: verde 5s → amarillo 2s → rojo 5s → repite.
  • El botón 1 (GPIO5) es la petición de cruce peatonal: al presionarlo, el semáforo debe terminar su fase actual de forma segura y quedarse en rojo 8s antes de reanudar el ciclo.
  • El LED 4 (GPIO23) parpadea mientras el semáforo esté en rojo por petición peatonal — indicador de "cruce seguro".
Parte F · Decisión de diseño

Ustedes deciden: ¿polling o evento?

No se les dice cómo leer el botón — decidan si usan gpiod_line_get_value() en bucle o un mecanismo de evento, y justifiquen su elección con un comentario en el código. Piensen: ¿el semáforo necesita hacer otra cosa mientras espera al peatón?

Entregable: semaforo.c compilando y funcionando en su Raspberry Pi. Sin plantilla — el diagrama de conexión (sección 5) y las reglas de arriba son todo lo que reciben.
